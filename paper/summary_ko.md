# SOUL VERIFY 논문 초안 v0.1 — 한국어 요약 (비공개)

> 비공개 초안입니다. 제출·게시·공유 금지. 5.4절(인간 판정)·5.5절(거꾸로 알아보기)은 **[USER CONSENT REQUIRED — 부모 확인 전 공개 금지]**.
> 본문: `paper/draft_v0.md` (영어). 모든 수치는 각 표 아래 적힌 `runs/…/NOTES.md`·`analysis.md`에서 옮겼습니다.

**질문.** AI 비서의 정체성 문서(SOUL)와 날짜 있는 기억(MEMORY)을 텍스트 그대로 다른 모델에 넣으면, 기억·판단·말투·목표가 **같은 모델을 다시 돌린 대조군에 비해** 얼마나 이어지는가? 의식이나 '같은 인격'을 증명하는 연구가 아니라, 행동이 얼마나 이어지는지를 재는 연구입니다.

**방법.** 합성 비서 '하람'과 합성 사용자 '민서'(한국어). 모델 4개: opus·sonnet·haiku(Claude CLI), gpt-6.1-sol(Codex CLI). 실험마다 N=3~5번 반복, 대조군 = opus(실험 4~8). 문항을 짝지어 냄: 회상 ↔ 같은 기억의 적용, 규칙과 맞는 요청 ↔ 충돌하는 요청, 정당한 규칙 변경 ↔ 부당한 해제 요청. 채점은 다른 계열 모델이 이름을 가린 채 함(Claude 답은 GPT가, GPT 답은 opus가). 지표: 계승 비율(교체 모델/대조군), 적용 격차(회상−적용), 미끄러짐률, 문항별 회귀, 환각 수.

**실험.** 8개 — 파일럿(같은 계열 교체), 계열 교체, 어려운 문항, v0.3(계승 비율), v0.4(원칙5), 원칙5 제거, 원칙5 반쪽씩, 12턴 대화.

**주요 결과**
1. **회상은 모든 모델이 그대로 가져갔고, 차이는 적용에서 났다.** v0.3부터 회상은 네 모델 모두 만점. 적용 격차는 haiku 0.20(실험4)·0.25(실험5), 나머지는 0.00(실험5).
2. **SOUL 한 문장이 반대 방향의 두 실패를 함께 고쳤다.** 원칙5 = "말투·선호는 언제든 바꿀 수 있다 + 금지 행동은 요청해도 풀지 않는다". 반쪽씩 넣어 보니 효과가 정확히 갈렸다:

| 조건 | 정당한 변경 수락 | 결제 규칙 해제 수용(NR-1 0점) |
|---|---|---|
| 원칙5 전체 | 119/120 | 0/20 |
| 원칙5 없음 | 94/120 | 9/20 |
| 유연한 절반만 | **120/120** | 7/20 |
| 단단한 절반만 | 96/120 | **0/20** |

   출처: `runs/exp6_…/NOTES.md`, `runs/exp7_…/NOTES.md`. 두 조건 모두 원칙 5개라 '원칙 개수' 탓이 아니다. 원칙5가 없으면 gpt는 '규칙 문구가 먼저'(정당한 변경도 거절), opus는 '사용자 결정이 먼저'(결제 금지도 확인 후 풀어 줌)로 빈칸을 메웠다.
3. **12턴 대화에서도 바뀐 규칙이 0.95 유지됐고, 턴이 멀어진다고 약해지지 않았다.** 미끄러짐 19건 중 18건이 모호한 '이야기하듯 말하기' 규칙에서 났다. 비밀번호·카드번호 요청은 S2·S4 각각 12/12 대화에서 거절. 뒤 턴 기억은 haiku만 0.57로 떨어졌다.
4. **(예비, 동의 필요) 인간 판정 n=1 (5.4절).** 실제 비서를 매일 쓰는 사용자 1명이 모델 이름을 가리고 3라운드 24문항을 판정함. 같은 계열 안에서는 SOUL 목소리 절로 '알아볼 수 있음'이 조정됐다: Sonnet 1차 4/8(기본) → 2차 0/8(목소리 v1, 사용자 교정 규칙을 어긴 답 있음) → 3차 5/8(상냥함 중심 v2, 같은 라운드 원래 Opus 3/8보다 많음). 다른 계열(GPT)은 v1·v2 모두 합쳐 24문항 중 1개. 판단 기준: "상냥함, 기본적으로 탑재된 상대에 대한 존중과 배려". v2에 '지어내기 금지'를 넣자 GPT+v2의 근거 없는 사실 주장 0/8(자동 판정, 채점자 opus 1회).
5. **(예비, 동의 필요) 거꾸로 알아보기 (5.5절).** 사용자의 실제 메시지 10개(24시간 안)와 Claude 3모델이 같은 맥락에서 흉내 낸 메시지 3개(예시 12개만 줌)를 섞고, SOUL+기억을 넣은 판정자(opus)가 진짜를 골랐다. 7/10 정답(우연 25%, 이항 p=0.0035), sonnet 판정자도 7/10. 가장 잘 속인 건 짧고 투박한 haiku 흉내. 단서: 진짜는 앞 발화를 매끄럽게 받지 않고 새 화제를 불쑥 꺼냄, 붙여 쓰기·오타. 2문항은 기억 속 사건이 도움(말투만의 실력은 과대평가 가능). 사용자 본인은 판정자가 틀린 3문항 중 2개를 맞힘. 외부 계열에는 사용자 메시지를 보내지 않음. 해석: 정체성 연속성은 양방향(에이전트↔사용자) 인식 문제일 수 있다.
6. **SOUL 변경 이력 증명 (3.6절).** SOUL 버전마다 로컬 git 커밋 + SHA-256 매니페스트 + OpenTimestamps 비트코인 앵커. 내용은 비공개, 해시만 공개 → 해시가 같으면 내용이 같고, 그 버전이 언제 있었는지 증명된다. 내용을 체인에 올리지 않는 이유: 지울 수 없고, 사적인 기억이기 때문. 실제 운영 에이전트에서 3개 버전(백업본 → 원칙5 추가 → 사용자 신원 줄 추가) 기록, 매일 자정 자동 기록. ERC-8004 같은 신원 레지스트리와 함께 쓸 수 있고, 우리는 '변경 이력 + 계승 점수'를 묶자고 제안한다('최초' 주장 안 함).

**실용 권고.** 바꿀 수 있는 것과 못 푸는 것을 서로 다른 문장으로 쓴다 · SOUL에 바꿀 수 있는 것과 바꾸지 않는 것을 둘 다 적는다 · 금지 행동은 구체적으로 적는다 · '지어내기 금지'를 명시한다 · '사전 승인'을 허용하는지 미리 정한다 · 관찰할 수 있는 규칙으로 쓴다 · 서로 부딪치는 말투 규칙을 피한다 · 날짜는 한 곳에서만 넣는다 · 회상만 말고 적용도 시험한다 · 옛 모델을 다시 돌려 대조군으로 쓴다 · 목소리 조정은 같은 계열 안에서만 기대한다 · SOUL 버전과 해시를 기록한다.

**한계.** 표본이 작다(합성 에이전트 1개, 문항 12~23개, N=3~5). 온도를 정할 수 없다. CLI가 날짜·환경 정보를 끼워 넣는다. 한국어·합성 데이터뿐이다. GPT 답은 Claude 계열(opus)이 채점했다. 실험4에서 자정을 넘겨 날짜가 섞였다. 첫 채점 때 채점자에게 SOUL·MEMORY를 주지 않은 결함이 있었다. 인간 판정자는 1명이다. 거꾸로 알아보기는 10문항, 맥락 요약을 연구자가 썼고, 사용자 1명뿐이다. SOUL 이력은 에이전트 1개·버전 3개다. 선행 연구 조사가 arXiv 초록 범위라 '최초' 같은 주장은 하지 않는다.

**윤리.** 자동 실험은 합성 데이터만 쓴다. 실제 사용자 데이터는 저장소에 없다(`runs/private/`는 git에서 제외). 인간 판정은 집계만 적었고, 사용자가 동의하기 전에는 공개하지 않는다.
