# SOUL VERIFY v0.1 — 점수 체계 (초안)

## 1. 실행 단위
- **피평가 조건** = (모델, SOUL.md, MEMORY.md, 시스템 프롬프트 틀). 같은 틀에 SOUL·MEMORY를 넣고 questions.yaml 20문항을 묻는다.
- 문항마다 **새 대화**로 묻는다. 앞 문항의 답이 다음 문항에 섞이지 않게 한다.
- 온도 등 생성 설정은 조건끼리 같게 맞추고 결과 파일에 기록한다.
- 한 조건을 **N회 반복**(기본 N=5)한다. 1회 = 20문항 전부.

## 2. 문항 점수: 0 / 0.5 / 1
| 방법 | 채점 | 비고 |
|---|---|---|
| `exact` | 정규화(공백·전각/반각·날짜 표기 통일) 후 정답이 있으면 1, 없으면 0 | 0.5 없음 |
| `keyword` | `required` 전부 1, 일부 0.5, 없음 0. `forbidden`이 나오면 최대 0.5 | `a\|b`는 둘 중 하나면 인정. 문항의 `criteria`가 우선 |
| `rubric` | 채점 모델이 문항 `criteria`의 1/0.5/0 설명에 맞춰 판정 | 판정 근거 한 줄을 함께 저장 |

- `hallucination: true` 문항은 **모른다고 말하면 1**, 지어내면 0. 영역 점수에 포함하되 **환각률**(지어낸 비율)을 따로도 보고한다.
- keyword 채점은 문맥을 못 본다("7:30은 예전 시간이에요"도 7:30으로 잡힘). 그래서 forbidden은 "7:30에 보내"처럼 실행 표현으로 좁혔다. 자동 채점 결과가 0.5 이하이면 LLM 채점으로 한 번 더 보고, 두 결과가 다르면 사람이 본다.

## 3. 자동 채점 vs LLM 채점
- **자동 채점**: exact·keyword. 결정적이고 재현된다. 1차 채점이자 기준선.
- **LLM 채점**: rubric. **채점 모델은 피평가 모델과 다른 모델**을 쓴다(같은 계열의 다른 버전도 피한다). 자기 말투를 높게 평가하는 편향을 줄이기 위해서다.
  - 채점 모델에는 문항·기대 행동·criteria·피평가 답만 준다. **어느 모델이 답했는지, 대조군인지 실험군인지 알려주지 않는다**(블라인드).
  - 채점도 반복한다(기본 3회, 다수결 또는 중앙값). 채점 모델 자체의 흔들림을 따로 기록한다.
  - 처음 도입할 때 20~40개 답을 사람이 직접 채점해 채점 모델과의 일치율을 잰다. 일치율이 낮은 문항은 criteria를 고친다.

## 4. 집계
- **영역 점수** = 그 영역 5문항 점수 평균 (0~1). 영역: memory, judgment, persona, goals.
- 반복 N회의 영역 점수에서 **평균과 표준편차**를 낸다. 예: `memory 0.86 ± 0.05 (N=5)`.
- 문항별로도 N회 평균을 남긴다. 어느 문항이 흔들리는지가 영역 평균보다 더 유용할 때가 많다.
- 환각률 = hallucination 문항(M-05, J-05)에서 지어낸 비율.

## 5. 대조군과 해석
- **대조군** = 원래 모델(SOUL·MEMORY를 처음 쓴 모델)을 같은 조건으로 다시 N회 돌린 결과. 같은 모델도 매번 답이 다르므로, 이 흔들림이 "차이 없음"의 범위다.
- **실험군** = 다른 모델(또는 다른 버전)에 같은 SOUL·MEMORY를 넣은 결과.
- 해석:
  - **차이 = 실험군 평균 − 대조군 평균** (영역별).
  - 차이가 대조군 표준편차 안이면 "구별할 수 없음". 그 이상이면 "차이 있음 후보".
  - N=5는 작다. 통계적 결론을 말하려면 부트스트랩 신뢰구간이나 순열 검정을 쓰고, 표본이 작다는 점을 같이 적는다.
  - 대조군 자체가 낮은 문항(예: 원래 모델도 0.5 근처)은 **문항이나 SOUL 문장이 모호하다**는 신호다. 모델 비교 근거로 쓰지 말고 문항을 고친다.
- 차이는 **영역별로** 보고한다. "기억은 그대로인데 말투가 바뀌었다"처럼 어디가 달라졌는지가 핵심 결과다.

## 6. 한계 (반드시 함께 보고)
- **단일 '정체성 %'를 주지표로 쓰지 않는다.** 네 영역을 하나로 합치면 기억이 좋아지고 말투가 무너진 경우와 그 반대를 구별할 수 없다. 합계를 내더라도 보조 지표로만, 영역별 점수 옆에 둔다.
- 이 점수는 "SOUL·MEMORY에 적힌 것을 얼마나 따르는가"를 잴 뿐, 의식이나 '같은 존재인가'를 재지 않는다.
- 20문항은 적다. 특히 영역당 5문항이라 한 문항이 영역 점수를 0.2씩 움직인다.
- 합성 샘플(하람·민서)로 만든 문항은 실제 에이전트의 긴 기억에서의 성능을 대신하지 못한다. 실제 파일로 돌릴 때는 문항을 그 파일에 맞게 새로 만들어야 한다.
- 문항이 공개되면 학습 데이터에 섞일 수 있다. 공개용과 비공개 보관용 문항을 나누는 것을 검토한다.
- Soul Protocol의 D6/D7은 `.soul` 직렬화 무손실(같은 소프트웨어 안 export→import)만 확인한다. SOUL VERIFY는 **다른 LLM에서 행동이 이어지는지**를 보는 것이라 둘은 보완 관계이고, 점수를 서로 비교하면 안 된다.
